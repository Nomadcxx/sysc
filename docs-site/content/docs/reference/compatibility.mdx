## Compatibility and support

SYSC v0.1.1 defines installer routes and publishes the assets listed below. SYSC has not published a qualification matrix for specific machines and desktop configurations.

## Installer and suite

| Area | Release behavior and qualification limit |
|---|---|
| Installer binary | The v0.1.1 workflow publishes Linux amd64 and arm64 installers with CGO_ENABLED=0. Source builds use the Go version in [go.mod](https://github.com/Nomadcxx/sysc/blob/v0.1.1/go.mod). Installer assets do not establish component support for both architectures. |
| Full suite architecture | Every enabled component in the [v0.1.1 pin manifest](https://github.com/Nomadcxx/sysc/blob/v0.1.1/internal/pin/pin.json) has an amd64 asset. No complete arm64 set exists, and the installer refuses to install the suite on arm64. |
| Distribution gate | Preflight accepts the Arch family. Its matcher checks arch, cachyos, manjaro and endeavouros in ID or ID_LIKE. The source does not qualify every derivative; other full-suite distro support remains unknown. |
| Compositor | SYSC targets Niri first. In a Wayland session, preflight requires NIRI_SOCKET. Without WAYLAND_DISPLAY, the installer allows a non-graphical run and enables units. This does not establish support for other compositors or a complete desktop configuration. |
| User services | The installer writes suite programs and units to the installing user's systemd manager. Check each component's pinned release for runtime dependencies. |

## gSlapper package routes

For gSlapper, the installer uses yay or paru on Arch-family systems. It uses a .deb for Debian 13, a separate .deb for Ubuntu 24.04, the Debian 13 package for Ubuntu 25.x, and an .rpm for Fedora 42 and later. These routes install gSlapper; suite preflight still requires the Arch family.

## Privileges and build requirements

Run the installer as a normal user. Preflight refuses root. The installer writes suite files under the user's home and units for systemd --user. A native gSlapper package install can invoke sudo; an Arch-family install runs through the user's yay or paru helper. Check task results after installation because an optional package task can fail while the remaining tasks continue.

The release builds the installer as a Go binary with cgo disabled. To build it from source, use the Go version in the tagged go.mod. Check each component's pinned release for runtime libraries and build requirements; treat them as unknown when the source does not establish them.

## Qualification status

The installer source lists routes and refusal checks. It does not provide a tested distro × architecture × compositor matrix. Mark a machine or desktop configuration unknown until a test record covers it. Standalone component support does not expand the full suite's installer gate.
