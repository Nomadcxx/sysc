Use the current default-branch commit for behavior guidance. Use the release tag for the version that SYSC v0.1.4 installs. A branch can move ahead of the suite pin. SYSC does not install projects that its manifest does not pin.

The v0.1.4 installer installs sysc-terminal v0.3.1 as a wallpaper executable that the shell manages, seeds tray presentation in a new config when sysc-tray installs, and removes plugin selections that did not install executables. These changes also apply to source builds.

We checked these default branch heads on 2026-10-15. Each source link opens a full commit. The pin column reflects installer v0.1.4. When behavior changes, update the affected article and this record together. These commits show which source the docs used; component development continues independently.

## Plugin SDK version

At the recorded [`sysc-plugins` revision](https://github.com/Nomadcxx/sysc-plugins/blob/6a8130a47fbd27ca93ccd3ecc62b78d0814587f2/go.mod), Go selects sysc-shell v0.2.0, the same release this suite installs. That module supplies `plugin/v1` and `plugin/lint`, so plugin tests and the installed shell use matching public types and constants.

The v0.1.3 manifest lists the suite pins. The installer workflow publishes installer binaries; each component publishes its own assets. Check the component release before inferring availability from the installer's architecture matrix. Component articles will link the relevant source files and call out behavior differences from the suite pin.
