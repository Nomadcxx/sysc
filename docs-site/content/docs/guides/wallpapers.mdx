**SYSC v0.1.1 pins:** sysc-shell v0.1.0, sysc-walls v1.0.2 and gSlapper v1.5.1. The installer disables sysc-terminal. The [source record](/docs/reference/sources) links each reviewed commit.

Use one wallpaper owner per output. sysc-shell can manage static image backends, gSlapper video and image playback, or sysc-terminal effects. sysc-walls owns the idle screensaver, not the desktop background.

## Choose a backend

### Static image

The shell can set an image with awww or swaybg. Choose the backend in the shell's Wallpaper settings. The shell owns the process and its Wayland surface.

### Video or image through gSlapper

The shell can launch gSlapper for each output and manage its control socket. For a manual run, first list connector names:

~~~sh
gslapper --help-output
~~~

A manual video or image command starts a wallpaper process:

~~~sh
gslapper -o "loop fill" OUTPUT /path/to/video.mp4
gslapper -o fill OUTPUT /path/to/image.jpg
~~~

Replace OUTPUT with a connector from the output list. Do not run a manual process on an output that sysc-shell already manages. See [gSlapper](/docs/components/gslapper) for playback limits.

### Live terminal effects

sysc-terminal draws sysc-Go effects on Niri's background layer. It runs one process per output and uses a separate IPC socket for each. SYSC v0.1.1 installs no sysc-terminal executable or user unit; its pinned sysc-shell module still declares the Go dependency. Install the executable separately to use Terminal Art. See the [sysc-terminal guide](/docs/components/sysc-terminal) for its exact source install and discovery check.

### Idle screensaver

sysc-walls watches idle activity and launches screensaver animations in Kitty terminals. The shell configures it from Screensaver settings, while the sysc-walls user service owns the daemon. Check the unit with:

~~~sh
systemctl --user --no-pager status sysc-walls.service
journalctl --user -u sysc-walls.service -b --no-pager
~~~

Do not configure sysc-walls as a wallpaper backend. It starts after the idle timeout and stops when activity resumes.

## Diagnose a blank output

1. Run the backend's read-only output listing command.
2. Check that the selected output name matches the compositor's connector.
3. Check the owning process or user unit and read its journal.
4. Confirm that no second wallpaper process targets the same output.
5. Check the [Niri session environment](/docs/guides/niri-session) before changing service startup.

Current shell source manages wallpaper child processes. The exact capabilities in SYSC v0.1.1 follow its pinned sysc-shell and sysc-walls releases; the [source record](/docs/reference/sources) lists both.
